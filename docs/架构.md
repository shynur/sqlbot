1. 程序会把 LLM 前端与 RDBMS 耦合, 通过 RAG 以提供更加有效的上下文.
2. SQL 会在数据库的副本上运行多轮, 反馈运行结果, 逼近最佳答案.
3. LLM 后端可以替换, 也可以同时使用多个 LLM, 充分利用 LLM 快速增长的算力.
4. 查询结果对 LLM 来说是不可见的, 仅知晓表的元数据 (行列信息), 增强隐私保护.
5. 对于可能修改数据库数据的查询, LLM 会给出对应的解释, 请求确认, 提高安全性.
6. 缓存用户认为有用的 SQL, 通过 LLM 比较两次 question 之间的相似度以复用 SQL, 提高下一次查询的精准度.

- 程序
  1. * 用户提问
  2. * 数据预处理
  3. / 生成 prompt
  4. LLM 处理
  5. 试运行
  6. 确认执行
  7. 调试
  8. 打印结果
  9. 反馈
- 用户提问 (使 question 具体, 减少误解)
  1. * 打开指定的 database
  2. * 发送 question
  3. * 判断 question 是否合理
  4. * 如果模糊则提供几个解释供用户选择, 太过模糊则直接驳回
- 数据预处理 (RAG)
  1. * 执行预定义 SQL 以输出 database 元数据
  2. * 元数据 to 自然语言
  3. * 裁剪出对 answer 有用的信息
  4. * 为 question 构建上下文
- 生成 prompt
  1. 对 "反馈" 步骤中的 question 依次查询, 比较特征吻合度
    - 吻合: 是重复问题, 复用 SQL 语句
    - else: 构建 prompt 模板
- 试运行
  1. * 完整复刻一份 database
  2. 运行 LLM 输出的 SQL
  3. 提取输出图表的行列元数据
  4. 元数据 to 自然语言
  5. 反馈给 LLM
  6. 视情况重新返回 "LLM 处理" 这一步
- 确认执行
  1. (如果是写操作) 将 SQL 发送到 LLM
  2. 返回对 SQL 执行后果的预测
  3. 用户确认
- 调试
  1. 打印 SQL 语句
  2. 用户可以选择修改 SQL 语句
- 打印结果
  - 读操作: 则直接打印
  - 写操作: 则清空 "反馈" 步骤的缓存
- 反馈 (可选)
  1. 用户告知 answer 是有效的
  2. (如果写只读操作) 缓存 question 与 SQL 语句
